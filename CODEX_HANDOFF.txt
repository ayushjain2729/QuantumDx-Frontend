==================================================
1. PROJECT OVERVIEW
==================================================

Project name
------------
quantumdx-frontend (package name); the UI brands itself as "QuantumDx | Clinical
Intelligence".

What the project currently does
-------------------------------
This is a client-only React prototype for a clinical/quantum-risk dashboard. It
renders mock patient screening data, a simulated hybrid-analysis workflow,
patient risk reports, a quantum-engine explainer, benchmark cards, and static
report cards. It does not connect to a real clinical system.

Main objective of the work in progress
--------------------------------------
The active task was a visual/experience redesign: replace the generic dark
dashboard/video treatment with a premium "Scrollcraft" spatial interface with
intentional layer depth, editorial headline composition, restrained parallax,
and a low-noise Three.js matrix/particle field that does not interfere with
clinical text or controls. The original product behavior was intentionally kept
in place while the visual system was changed.

Current architecture
--------------------
- One Vite/React single-page application (SPA).
- No React Router. `App` switches local `page` state among views.
- All feature/page components, mock patient data, and UI state are in
  `src/App.jsx`.
- Global stylesheet is `src/styles.css`.
- Ambient WebGL visual is an independent React component at
  `src/SpatialField.jsx`.
- Build output is the generated `dist/` directory.
- No server-side code, API route, worker, database module, or authentication
  module exists in the repository.

2. ORIGINAL/INTENDED GOAL
==================================================

No README, written product specification, issue tracker export, or design brief
exists in the repository. The following goal is therefore based on the active
task context and the implemented code, not on a repository-resident spec.

The intended result is a visually premium, hyper-immersive but readable clinical
intelligence dashboard. The redesign specifically called for:

- eliminating the blocky/generic AI-template appearance;
- a "Scrollcraft" architectural treatment with deep, overlapping visual layers;
- headlines that sit in a secure top layer and deliberately reach beyond an
  ordinary container/grid rhythm;
- restrained fluid parallax background elements;
- a production-conscious Three.js matrix/particle background reacting gently to
  mouse movement and scroll depth without visual noise;
- strong mobile behavior; and
- visual layer-depth/collision checking before completion.

The existing application content is explicitly prototype/demo content: clinical
screening, hybrid quantum/classical model status, QSVM labels, risk scores, and
benchmark values are presentation data rather than a connected diagnostic system.

Literal "GPT-6 Astra" and "WebMCP" engines/tools are not application
dependencies and are not present in this repository. The implemented substitute
is direct Three.js plus local headless-browser screenshot inspection. Do not
claim that a WebMCP test suite exists.

9. ARCHITECTURE & DATA FLOW
==================================================

Runtime flow
------------
1. `index.html` supplies `<div id="root">`.
2. `src/main.jsx` mounts `<App />` in React StrictMode and imports global CSS.
3. `App` starts on `page = "dashboard"`; local clicks modify `page` or selected
   patient ID.
4. `views` in `App` maps state to a React component. There is no URL routing.
5. `patients` and `getPatientRiskProfile` in the same module produce all display
   data. No network request is made.
6. `SpatialField` mounts once under the app shell. It lazy-loads Three.js if
   permitted, creates a transparent fixed canvas, and writes a few CSS custom
   scroll variables that animate atmospheric CSS elements.
7. The content shell/rail/header is placed above canvas/atmosphere by CSS z-index
   and pointer-event rules.

Data flow for a patient report
------------------------------
- Dashboard/Patients/Reports calls `onReviewPatient(id)`.
- `App.handleReviewPatient` updates `selectedPatientId` and changes `page` to
  `results`.
- `Results` runs a 150 ms `setTimeout` simulation and calls
  `getPatientRiskProfile(patientId, patients)`.
- That deterministic local function calculates labels/values and `Results`
  renders the derived profile.
- No data moves outside the browser and nothing is saved.

Analysis flow
-------------
- `Analysis` owns a local form object.
- Clicking Run sets `running = true`.
- After 1.7 seconds, it opens results for the entered ID.
- The quantum pipeline is visual state only.

Frontend → backend flow
-----------------------
NONE. No backend exists.

Backend → database flow
-----------------------
NONE. No backend/database exists.

APIs/authentication/external services
-------------------------------------
NONE FOUND. No fetch/axios/API route/auth token/auth provider/external service
integration appears in source. NPM registry URLs in `package-lock.json` are
dependency metadata only.

Important implemented architectural decisions
--------------------------------------------
- Keep the existing stateful demo SPA intact; redesign its shell rather than
  replacing its page components.
- Direct Three.js is isolated in `SpatialField.jsx`, rather than introducing
  React Three Fiber or placing canvas inside individual pages.
- Use CSS/JS fallback instead of making WebGL required for application content.

14. KNOWN BUGS / RISKS
==================================================

1. Current source is not final-build verified.
   - Risk: a syntax/bundling issue introduced in the final 13:26 changes could
     remain undiscovered despite earlier build success.
   - Mitigation: run `npm run build` first when resuming.

2. Mobile layout remains unproven after final edits.
   - Risk: document-level horizontal overflow or right-edge clipping at 390px/
     320px, especially around spatial hero text/button and compact navigation.
   - Mitigation: measure DOM widths across all views before applying another CSS
     patch.

3. No automated layer-depth/collision test exists.
   - Risk: future CSS changes can put canvas/atmosphere above interactive content
     or reintroduce overlap.
   - Mitigation: manual visual test now; automated visual smoke tests later.

4. `SpatialField` WebGL context restoration is not implemented.
   - Risk: if a WebGL context is lost, the field cancels animation and does not
     rebuild itself until component remount.
   - Mitigation: acceptable for decorative content if fallback remains readable;
     add context-restored rebuild only if device testing shows a need.

5. Production bundle and unused media are heavy.
   - Risk: `public/background.mp4` adds about 18 MB to `dist/` while no JSX uses
     it. Three.js emits a 724 kB uncompressed chunk and triggers Vite's size
     warning.
   - Mitigation: get approval and performance data before deleting/optimizing.

6. The project is a clinical-looking mock without clinical protections.
   - Risk: static/deterministic scores and recommendations can be mistaken for
     real clinical decision support if deployed without clear controls.
   - Mitigation: do not connect real patient data or present it as diagnosis
     without explicit domain, compliance, privacy, safety, and backend work.

7. Placeholder UI controls have no behavior.
   - Affected: search/filter, add patient, settings, notifications, report
     generation, PDF export.
   - Risk: users may assume actions happened when they did not.
   - Mitigation: either implement with a defined product contract or visibly
     mark/disable prototype-only controls.

8. Styling is cascade-heavy.
   - Risk: base CSS and appended Scrollcraft overrides share selectors and media
     widths. A new earlier rule may appear ineffective; a tail rule can affect
     legacy screens unexpectedly.
   - Mitigation: inspect computed styles and add narrow tail overrides for
     immediate fixes; refactor only with a baseline and adequate scope.

9. Reproducibility risk from `"latest"` dependency ranges.
   - `package-lock.json` currently pins known versions, but `package.json` uses
     `latest` for React/Vite/plugin packages.
   - Mitigation: use the lockfile for exact installs; consider pinned ranges only
     under a deliberate dependency-management change.

10. No version control exists in this directory.
    - Risk: there is no commit/diff safety net for changes.
    - Mitigation: preserve files, consider initializing a repository only with
      user authorization, and make narrow changes after backups/inspection.

11. Simulated Analysis timeout has no explicit cancellation path.
    - Risk: navigating away during its 1.7-second timer may call state logic from
      an unmounted view (React usually tolerates this, but it is not ideal).
    - Mitigation: add timer cleanup only if behavior work is authorized.
